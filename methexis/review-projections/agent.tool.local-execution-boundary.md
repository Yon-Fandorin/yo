# Local model-tool 실행 경계

## 계약

Yo-managed model loop는 frontend-independent registry가 admit한 tool만 노출해야 합니다. 각 registered tool은 stable `ToolId`, unique wire name, safe description, versioned JSON input schema, typed effect와 approval requirement, injected execution-host handle을 가져야 합니다. Registry와 admission policy는 `yo-core`가 소유하고 execution host는 실제 OS 또는 remote workspace effect를 소유하며 그 effect를 Model Connector에 노출하면 안 됩니다.

Effective tool registry는 model request 하나 동안 고정해야 합니다. Model에는 admitted function-tool projection만 보내야 합니다. Provider built-in tool, provider-hosted code execution, direct provider MCP execution은 미루며 OpenAI-compatible endpoint 때문에 암묵적으로 enable하면 안 됩니다.

반환된 function call은 approval이나 execution 전에 exact registered tool 하나를 resolve하고 complete accumulated JSON argument를 validate해야 합니다. Invalid JSON, schema mismatch, unknown 또는 duplicate call identity, unavailable tool, configured argument bound 초과는 effect를 dispatch하지 않고 typed Tool Activity failure가 되어야 합니다. Approval은 exact Turn, call identity, ToolId, normalized argument digest, effect class, execution host에 bind해야 합니다. Stale 또는 mismatched response는 call을 authorize하면 안 됩니다.

Dispatch 뒤에는 call 하나당 local execution attempt를 최대 하나만 허용해야 합니다. Timeout, transport ambiguity, cancellation, executor failure, lost output 때문에 effectful tool을 자동 반복하면 안 됩니다. Executor는 bounded text output과 필요한 explicit truncation을 포함한 typed completed, failed, interrupted result를 반환해야 합니다. Session Journal이 exact call, approval, execution attempt, tool result를 correlate한 뒤에만 model에 result를 제출할 수 있습니다.

Execution progress와 absolute work budget은 서로 구분되어야 합니다. 모든 execution host는 유한한 progress-inactivity deadline과 이를 reset하는 정확한 signal을 정의해야 합니다. 첫 local command tool은 각 non-empty stdout 또는 stderr chunk를 progress로 취급하고 해당 progress마다 5분 inactivity window를 reset해야 하며, process가 살아 있어도 5분 동안 이런 output이 없으면 attempt를 실패시켜야 합니다. Agent policy는 absolute execution deadline 하나를 추가로 제공할 수 있습니다. 이 deadline은 기본값이 없음이고 attempt 하나에 대해 한 번 시작하며 output이나 다른 progress로 reset되면 안 됩니다. Cancellation은 두 wait를 모두 중단해야 하며 timeout 또는 cancellation은 유한한 termination, reap, output-drain bound를 사용해야 합니다. Diagnostic은 inactivity, agent가 제공한 absolute deadline, cancellation, cleanup failure를 구분해야 합니다. 어느 결과도 자동 retry를 허용하지 않습니다.

기본은 model order의 serial execution입니다. Scheduler가 approval scope와 mutable resource lease가 disjoint임을 증명할 때만 concurrent execution할 수 있습니다. Completion order와 관계없이 result publication과 model submission은 stable model-call order를 사용해야 합니다. Cancellation은 undispatched call을 막고 active executor의 prompt cancellation을 요청하며 effect가 없었다고 증명할 수 없으면 explicit interrupted result를 보존해야 합니다.

Tool name, schema, argument, output은 model-visible semantic history이며 Session Journal의 bounded persistence와 redaction을 따라야 합니다. Execution-host diagnostic과 prohibited secret은 semantic history 밖에 둬야 합니다. Exact replay는 historical tool을 다시 실행하지 않고 recorded function-call과 result relation을 재현해야 합니다.


첫 registry schema dialect는 closed `yo.tool-schema/v1` subset입니다. 각 node는 object, array, string, number, integer, boolean, null 중 하나가 필요하며 `description`, `properties`, `required`, `additionalProperties`, `items`, 같은 type의 non-empty `enum`만 허용합니다. 각 요청 file은 independent observation이지 multi-file snapshot이 아닙니다. Host는 이미 연 workspace directory 아래에서 symlink를 따르지 않고 resolve하고 regular UTF-8 file 하나만 허용하며, 다른 hard link를 통해서도 credential identity를 거부해야 합니다. 열린 file 하나의 상한은 16,777,216 byte입니다. Host는 device, inode, size, modification time, change time을 capture하고 descriptor 하나를 forward로 읽어 bounded byte image를 만든 다음 같은 metadata를 다시 capture합니다. 두 capture와 observed byte length가 모두 일치할 때만 item을 허용합니다. 다르면 `changed_during_read`입니다. Admitted line total, window, content는 이 captured image만으로 계산합니다. 이는 ordinary concurrent local filesystem write를 탐지하지만, 관찰값을 바꾸지 않고 byte를 바꿀 수 있는 filesystem에 대한 adversarial snapshot primitive는 아닙니다. Batch preflight 뒤 path 또는 file failure는 bounded item error 하나를 만들며 성공한 sibling item을 버리지 않습니다. 반면 cancellation은 partial batch output을 버리고 later item을 열지 않은 채 interrupted call 하나를 반환해야 합니다.

Line window는 LF byte를 separator로 사용합니다. Final LF는 앞 line을 끝내지만 추가 line을 만들지 않습니다. Empty file에는 logical line이 0개입니다. LF 앞 CR을 포함한 다른 모든 byte는 content로 남습니다. 모든 JSON string은 다음 closed RFC 8259 escape rule을 사용합니다. `edit_file`은 path 하나와 1~256개의 exact `{oldText, newText}` object가 든 ordered `edits` array를 받아야 합니다. 각 `oldText`는 non-empty UTF-8 string이며 같은 captured original regular file에서 정확히 한 번 match해야 합니다. Match는 complete non-empty `oldText` byte sequence가 나타나는 모든 candidate byte position이며 overlapping occurrence도 셉니다. 따라서 `aaa`에서 `aa`는 match 두 개라 ambiguous입니다. 모든 match는 같은 original에서 계산하고 edit 사이에 overlap 또는 nesting이 없어야 하며, end에서 beginning 방향으로 적용하여 array order가 location을 바꾸지 않게 합니다. Absent 또는 ambiguous match, overlap, identical complete result, malformed input, publication 전 cancellation, unsafe path, non-UTF-8 file, credential identity, 16,777,216 byte보다 큰 original은 file을 바꾸지 않고 실패합니다. Empty `newText`는 유효하지만 complete planned result는 최대 16,777,216 UTF-8 byte여야 합니다. `write_file`은 exact `path`와 최대 16,777,216 byte의 complete UTF-8 `content`를 받아야 하고, 이미 존재하는 workspace directory 아래 regular file 하나를 atomically create 또는 replace해야 합니다. Named-file publication은 collision-safe same-parent temporary entry 하나를 create/remove하고 named target entry를 create/replace할 수 있으며, 그 entry operation에 따른 incidental parent-directory metadata change가 발생할 수 있습니다. Directory object를 create, delete, rename하거나 permission을 바꾸면 안 됩니다. New file은 ordinary process-umask-derived mode를 사용하고 replacement는 original에서 capture한 permission bit를 보존합니다. Symlink, non-regular target, credential identity, unsafe path component, publication 전에 이긴 cancellation, validation failure, write failure는 prior target을 그대로 두고 owned temporary state를 제거합니다. 두 mutation tool 모두 anchored workspace 밖에 쓰거나 target/ancestor symlink를 따르거나 named file 외의 것을 바꾸거나 partially written file을 publish하거나 ambiguous attempt를 retry하면 안 됩니다. 둘 다 `read_files`와 같은 최대 1,024-byte control-free workspace-relative path admission을 사용합니다.

Generic argument와 semantic admission이 mutation을 dispatch한 뒤 success는 `ToolExecutionOutcome::Completed`, `truncated = false`, insignificant whitespace와 trailing newline이 없는 compact UTF-8 JSON 하나를 반환해야 합니다. `edit_file` exact key order와 shape은 `{"path":<path>,"status":"ok","replacements":<count>}`, `write_file`은 `{"path":<path>,"status":"ok","bytes":<content-byte-count>}`입니다. Host failure는 `ToolExecutionOutcome::Failed`, `truncated = false`, exact key order `{"path":<path>,"status":"error","error":<class>}`입니다. Closed execution class는 `unavailable`, `non_utf8`, `too_large`, `changed_during_read`, `match_absent`, `match_ambiguous`, `overlapping_edits`, `no_change`, `scratch_unavailable`, `scratch_changed`, `write_failed`, `publication_failed`, `cleanup_failed`, `operation_failed`입니다. Narrower OS diagnostic은 semantic gate를 넘으면 안 됩니다.

Dispatch 뒤 authoritative total condition-to-class map은 다음과 같습니다. Unsafe, missing, symlink, non-regular, credential, inaccessible target 또는 parent는 `unavailable`이며 missing `edit_file` target과 target capture, metadata, read error를 포함합니다. Captured edit source가 UTF-8 decode되지 않으면 `non_utf8`, captured source 또는 complete planned output이 16,777,216-byte bound를 넘으면 `too_large`, 두 번째 metadata capture가 실패하거나 device, inode, size, modification time, change time, observed length가 바뀌면 `changed_during_read`입니다. `edit_file`은 request order로 original에 대한 edit을 검사합니다. 처음으로 old text match가 0개면 `match_absent`, 두 개 이상이면 `match_ambiguous`입니다. 모든 edit이 match 하나를 가진 뒤 overlap 또는 nesting이 있으면 `overlapping_edits`, 그 외 complete result가 같으면 `no_change`입니다. Cryptographic random source failure, non-collision scratch-create error, 16개 exclusive scratch-name attempt 소진은 `scratch_unavailable`입니다. Owned descriptor write 또는 publication mode 적용 실패는 `write_failed`입니다. Final prepublication pathname이 absent, foreign, non-regular 또는 credential identity이면 `scratch_changed`입니다. Atomic rename 하나의 실패는 `publication_failed`입니다. 위에 배정되지 않은 worker, join, internal host failure만 `operation_failed`이며 catch-all이 더 좁은 class를 대신하면 안 됩니다.

Pre-dispatch schema와 semantic admission이 먼저 실행되고 기존 validation code를 사용합니다. 여기에는 argument-count, string, path-byte, control-character, input-content bound가 포함됩니다. Instance lock을 잡은 뒤 `edit_file`의 fixed phase order는 target resolve/capture, source size 강제, read와 metadata 재capture, changed capture 거부, UTF-8 decode, array order의 requested match 평가, cross-edit overlap 평가, identical result 탐지, planned-output size 강제, scratch allocate/write/mode, cancellation check, scratch identity verify, rename입니다. `write_file` 순서는 existing parent와 optional target resolve 및 replacement mode capture, scratch allocate/write/mode, cancellation check, scratch identity verify, rename입니다.

이 phase order에서 처음 관찰한 primary condition을 유지합니다. Cancellation은 다른 primary failure 전이면서 rename 시작 전의 required cancellation check에서 관찰된 경우에만 이깁니다. Primary failure 뒤 관찰한 cancellation은 이를 replace하지 않으며 rename 시작 뒤에는 이길 수 없습니다. Final check는 scratch identity보다 cancellation을 먼저 관찰하므로 동시에 보이는 cancellation과 scratch change에서는 cancellation이 primary outcome입니다. Rename success는 final Completed이고 cleanup이 필요 없습니다. 나머지 모든 terminal path는 required cleanup을 실행합니다. Owned descriptor close, scratch pathname classify, still-owned entry unlink 중 하나라도 실패하면 retained primary failure 또는 Interrupted를 항상 `cleanup_failed`로 override합니다. 이 순서는 exhaustive하며 같은 observed state에 대해 두 execution class 중 하나를 선택하면 안 됩니다.

모든 string은 `read_files` JSON escape rule을 사용하고 complete mutation result는 최대 2,112 byte입니다. Successful 또는 failed execution result는 correlated Tool Activity와 durable replay byte가 됩니다. Cleanup이 성공한 cancellation은 대신 `ToolExecutionOutcome::Interrupted`, exact output `interrupted`, `truncated = false`입니다. Pre-dispatch schema 또는 semantic rejection은 기존 stable `yo.tool.validation.*/v1` Tool Activity failure이고 execution attempt나 mutation-result JSON을 만들지 않습니다.

Local execution-host instance 하나는 그 instance가 dispatch한 `edit_file`, `write_file` attempt가 공유하는 exclusive in-memory workspace-mutation lock 하나를 소유합니다. Lock은 target capture 또는 temporary-file creation 전에 acquire하고 cleanup 또는 publication까지 유지하므로 정확히 그 host instance를 통한 두 mutation tool만 interleave할 수 없습니다. `run_command`, 같은 process의 두 번째 execution host, 다른 Yo process, 모든 non-Yo editor는 참여하지 않으며 이 portable revision에서 uncoordinated external publisher입니다.

각 tool은 complete output을 same-parent temporary regular file에 계획합니다. Host는 OS cryptographic random source의 최소 128 bit를 담는 independently generated name을 최대 16개 시도하고, 각 candidate를 platform equivalent `O_CREAT | O_EXCL | O_NOFOLLOW`, initial mode `0600`으로 만듭니다. Collision 하나는 candidate 하나를 소모하지만 colliding entry를 열거나 바꾸지 않으며, 모두 소진되면 target을 바꾸지 않고 실패합니다. 다른 same-UID process가 temporary pathname을 볼 수 있지만 host는 이를 model-visible output에 노출하면 안 됩니다. Complete content는 mode `0600`인 동안 씁니다. Publication 직전에 captured replacement mode 또는 new-file umask-derived mode를 적용합니다. Final mode가 허용한 process는 이 final window에 unpredictable temporary pathname에서 complete content를 볼 수 있지만 target path는 그대로입니다.

Host는 created descriptor와 device/inode identity를 유지합니다. Publication 직전에 cancellation을 확인하고 scratch pathname을 no-follow metadata lookup하여 정확히 그 regular, non-credential inode인지 요구합니다. Scratch path가 없거나 foreign replacement이면 primary class `scratch_changed`로 terminal cleanup에 들어갑니다. Observed foreign entry는 unlink 대상으로 선택하지 않고 target은 그대로입니다. Exact identity match만 atomic same-filesystem rename 하나로 진행합니다. 이 rename 성공이 operation의 linearization/publication point입니다. Rename 시작 뒤 cancellation은 이길 수 없습니다. Rename success는 Completed입니다. Rename failure는 target을 그대로 두고 같은 cleanup sequence를 실행하며 cleanup 성공 때만 `publication_failed`를 반환합니다.

Cancellation, write/mode failure, identity mismatch, rename failure를 포함하여 successful rename 전에 끝나는 모든 path는 scratch descriptor 사용을 멈추고 닫은 뒤 instance lock을 유지한 채 bounded cleanup sequence 하나를 실행해야 합니다. Cleanup은 no-follow identity lookup 최대 한 번과 unlink attempt 최대 한 번입니다. Absent name은 이미 clean합니다. Exact owned inode로 관찰한 entry는 unlink 한 번의 대상이고 foreign entry는 대상이 아닙니다. Observed owned entry를 classify하거나 unlink하지 못하면 `cleanup_failed`이며 Completed나 Interrupted가 아니고 scratch name이나 content를 노출하지 않습니다. Cleanup step은 retry하지 않습니다. 앞서 정의한 portable same-UID boundary는 cleanup identity check와 path-based unlink 사이에도 적용됩니다. 이후 foreign replacement는 guarantee 밖의 uncoordinated namespace publisher이며 atomic identity-checked unlink로 보호된다고 설명하면 안 됩니다.

Cleanup 성공 시 cancellation은 Interrupted, 다른 path는 primary stable failure class를 반환합니다. `cleanup_failed` result는 complete content가 unpredictable scratch path에, 경우에 따라 final mode로 남을 수 있고 target path는 publish되지 않았음을 뜻합니다. Instance lock은 앞서 나열한 uncoordinated publisher를 bind하지 않습니다. Yo capture와 rename 사이의 uncoordinated external content write, replacement, `chmod`는 publication point에서 overwrite될 수 있습니다. 첫 version은 portable external-writer compare-and-swap을 제공하지 않으며 제공한다고 주장하면 안 됩니다. Replacement는 captured permission bit를 사용하므로 uncoordinated concurrent metadata change도 overwrite될 수 있습니다.

Supported Unix의 portable API는 final pathname-identity check와 이어지는 path-based rename을 indivisible operation으로 만들 수 없습니다. Check 뒤 scratch entry를 unlink/replace하는 uncoordinated same-UID process는 이 revision의 guarantee 밖 external namespace publisher입니다. 이때 last-publisher-wins가 적용되며 success가 Yo-authored content, regular-file identity, credential identity, byte-count authenticity를 증명한다고 설명하면 안 됩니다. 위 unconditional named-file guarantee는 scratch pathname이 rename까지 retained inode에 bind된 동안만 적용합니다. 이 explicit content, metadata, target-entry, scratch-entry external-publisher boundary는 supported Unix target에서 같고 hostile-same-UID security boundary가 아닙니다. Future platform-specific descriptor-anchored publication revision이 이를 닫을 수 있습니다.

## 이유

Delegated backend는 다른 agent host 안에 tool policy를 숨깁니다. Native loop에는 model protocol이 approval을 우회하거나 side effect를 반복하거나 tool completion order를 semantic order로 오인하지 못하게 하는 explicit local boundary가 필요합니다. Output inactivity와 optional agent-owned absolute deadline을 분리하면 productive long command를 계속 허용하면서 silent stall을 탐지하고 cancellation을 보존할 수 있습니다. Bounded batch reader 하나는 competing read schema 두 개를 제공하지 않으면서 model round trip을 줄입니다. Exact-edit와 full-write operation은 작은 model에 compact mutation surface를 제공하고 anchored host 하나는 path, credential, atomicity, cleanup rule을 일관되게 유지합니다.
