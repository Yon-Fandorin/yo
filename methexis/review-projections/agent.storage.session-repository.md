# 세션 저장소와 용량

## 계약

저장 방식에 종속되지 않는 세션 저장소가 영속 세션 기록을 소유하며, 파일·SQLite·다른 물리 구조를 프런트엔드 계약으로 노출해서는 안 됩니다. 현재 제품은 로컬 구현을 제공하고, 원격 저장소는 같은 저장소 인터페이스의 추후 구현으로 남깁니다. 로컬 구현 범위에는 복제, 이중 쓰기, 충돌 해결이 포함되지 않습니다.

로컬 저장소는 기본으로 켜져 있어야 하고, 디렉터리와 파일 접근을 현재 사용자로 제한하며, 설정 가능한 용량 상한을 제공해야 합니다. 시간에 따라 기록을 만료시키거나 완료된 세션을 자동 삭제해서는 안 됩니다. 용량 상한 또는 저장 장치 문제로 영속 추가 기록을 할 수 없으면 기존 기록은 변경하지 않고, 활성 세션은 영속 추가 없이 메모리에서 계속 실행해야 합니다. 저장소 소유자는 모든 연결된 프런트엔드에 영속 기록이 끊긴 지점을 식별하는 타입화된 지속 알림을 보내야 합니다. 이 공백 뒤의 기록을 연속된 영속 이력이라고 주장해서는 안 됩니다. 용량이 복구되면 완전한 세션 스냅샷을 먼저 기록한 뒤에야 이후 증분 기록을 영속 이력으로 받아들일 수 있습니다.

## 이유

로컬 우선 인터페이스는 데이터베이스 선택을 고정하거나 과거 작업을 조용히 버리지 않으면서 즉시 재개와 진단을 지원합니다. 명시적인 용량 경고와 스냅샷 복구는 원격 저장소가 아직 미래 작업인 동안에도 이력을 정직하게 유지합니다.
