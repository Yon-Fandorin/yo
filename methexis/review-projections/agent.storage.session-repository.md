## 결정

세션 저장소는 내구성 있는 세션 레코드의 생명주기를 하나의 저장소 인터페이스 뒤에서 소유하며, 프런트엔드에는 파일이나 SQLite 같은 물리 배치를 계약으로 노출하지 않습니다. 의미적 세션 저널 레코드와 Request Audit 데이터는 이 소유 경계 안에서 논리적으로 구분되지만, 서로 독립된 세션 원본은 아닙니다. 초기 제품은 별도 Request Audit 저장소 인터페이스나 범용 append-log 추상화를 만들지 않습니다. 현재는 로컬 구현을 제공하며, 원격 저장과 향후 Request Audit의 물리적 분리는 실제 근거가 생겼을 때 도입합니다. 복제·이중 쓰기·충돌 해결은 현재 로컬 구현의 범위가 아닙니다.

첫 로컬 구현은 세션마다 하나의 명시적으로 버전이 붙은 append-only JSON Lines 로그를 사용합니다. 따라서 두 논리 영역은 현재 하나의 물리 가용성 경계와 하나의 용량 상한을 공유합니다. 이 로그는 payload가 없는 bounded Request 연결 레코드의 첫 내구 저장 위치입니다. Request 상세를 내구 저장하려면 먼저 영속 저장 전 redaction 계약과 구현된 게이트가 있어야 하며, 그전까지 상세는 프로세스 로컬의 휘발성 데이터입니다. Request 상세만을 위한 독립 retention이나 eviction은 첫 구현에서 제공하지 않습니다. JSONL은 교체 가능한 구현 세부사항입니다. 압축, 세그먼트, 인덱스, SQLite 투영, 대체 인코딩, 별도 Request Audit namespace는 측정된 근거가 있어야 도입할 수 있으며, 이후 저장 분리가 세션의 의미나 생명주기 조정 권한을 바꿔서는 안 됩니다.

복구는 전체 로그를 메모리에 올리지 않고 완결된 줄을 스트리밍으로 읽습니다. 불완전한 마지막 줄은 커밋되지 않은 꼬리로 취급하고, 완결된 줄의 손상은 오류로 보고합니다. 하나의 로컬 저장소 root에는 writer 하나만 허용하며, open 시 root를 안정적인 절대 경로로 고정합니다. 모든 물리 append 전에는 pending marker를 내구화합니다. rollback 완료를 확인할 수 없으면 marker를 남겨 이후 reader가 애매한 완결 줄을 재생하지 않고 해당 세션 로그를 격리합니다. 기록이 있는 세션을 다시 열거나 최초 세션 상태 읽기 실패에서 복구할 때는 그 전에 메모리 전용 간극이 없었다고 증명할 수 없으므로, 다음 증분 레코드보다 완전한 snapshot을 먼저 요구합니다.

로컬 저장소는 기본으로 켜지고 현재 사용자만 접근할 수 있게 제한하며 설정 가능한 용량 상한을 제공합니다. 기간 만료나 자동 삭제는 하지 않습니다. 용량 또는 저장 장치 문제로 append가 막히면 기존 레코드는 바꾸지 않고, 활성 세션은 내구 append 없이 메모리에서 계속됩니다. 저장소 소유자는 내구 cutoff가 특정 sequence인지, 확인된 빈 로그인지, 알 수 없는지를 구분하는 타입화된 지속적 storage-pressure 알림을 연결된 모든 프런트엔드에 보냅니다. 저장소는 이 간극을 가로질러 연속된 내구 suffix가 있다고 주장하지 않습니다. 용량을 다시 사용할 수 있게 된 뒤에는 완전한 세션 snapshot을 먼저 기록해야 후속 증분 기록을 재개할 수 있습니다.

## 이유

로컬 우선 접근은 데이터베이스 선택을 조기에 고정하거나 오래된 작업을 조용히 버리지 않으면서 즉시 재개하고 진단할 수 있게 합니다. 명시적인 압력 상태와 snapshot 복구는 원격 저장이 아직 미래 작업인 동안에도 이력을 정직하게 유지합니다. 버전이 있는 JSONL은 첫 내구 데이터를 사람이 살펴보고 스트리밍 복구할 수 있게 하며, 저장소 경계는 이후 저장 최적화를 열어 둡니다.
