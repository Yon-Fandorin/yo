# Korean Review Projection

## Translation

# 세션 이어가기와 계보

## 계약

이력 열람과 실행 가능한 이어가기는 서로 다른 기능이어야 합니다. 이어가기 기준점은 수락된 백엔드 요청, 그 요청과 연결된 안정적이고 재개 가능한 결과, 완전히 커밋된 의미 저널 경계, 이어가기에 필요한 버전이 명시된 백엔드 세션 locator를 식별해야 합니다. 이 ID와 locator는 bounded 세션 저널 연결 데이터이며 선택적 Request Audit 상세가 아닙니다. 요청 payload, header, revision·attempt 증거와 그 밖의 진단 상세는 이어가기 기준점을 만들거나 검증하는 데 필요해서는 안 됩니다.

Resume은 조건을 만족하는 가장 최신의 영속 기준점을 선택해야 합니다. 완료되지 않았거나 수락되지 않았거나 커밋되지 않은 뒷부분은 진단 증거로만 남기며 자동 이어가기 입력으로 사용해서는 안 됩니다. 영속 기준점이 없으면 yo는 저장된 세션을 읽기 전용으로 열어야 합니다. 사용자가 명시적으로 확인한 경우 부모와 출발 기준점이 없음을 기록하는 빈 자식 세션만 제안할 수 있으며, 커밋되지 않은 뒷부분을 재생하거나 다시 보내서는 안 됩니다. 복구 snapshot은 내구 발행과 모든 기준점 조건이 완료된 뒤에만 이후 기준점의 근거가 될 수 있고, snapshot만으로 기준점을 만들면 안 됩니다.

Native Resume을 지원한다고 알리는 백엔드는 기준점의 버전이 명시된 세션 locator로 다시 연결하고 반환된 세션 신원을 확인해야 합니다. 실패하면 저장된 세션을 읽기 전용으로 열고 새 세션으로 이어갈지 물어야 합니다. 사용자가 명시적으로 선택한 경우에만 부모·출발 기준점을 기록하는 자식 세션을 만들고 부모를 변경하지 않으며, 백엔드가 지원하는 정확한 재생을 통해 커밋된 의미 경계까지만 초기 상태로 사용해야 합니다. 지원하지 않는 정확도는 시작 전에 알려야 합니다. yo는 대체 세션을 몰래 만들거나 불확실한 요청을 다시 보내거나 새 세션을 Native Resume처럼 보여줘서는 안 됩니다.

## 이유

마지막 안정적 Request는 사용자에게 이해하기 쉬운 재개 지점이지만, 명시적인 기준점은 재시도, 부분 쓰기, 백엔드 손실을 안전한 이어가기 상태로 오인하지 않게 합니다.
