## 규칙

라우팅은 typed stable ProviderId, AccountId, ModelId를 사용합니다. Provider는 서비스 그룹, Account는 자격증명 범위, Model은 wire 모델 이름입니다. 새로 저장하는 ProviderId로 `host`를 사용할 수 없습니다. 다만 기존 durable `host` 좌표는 안정적인 자격증명, attribution, continuation identity를 가진 qualified ModelTarget으로 유지합니다. 외부 key는 `provider`, `account`, `model`입니다. 정확한 Responses, Chat Completions, Kimi Chat Completions dialect는 닫힌 registry를 통해 Connector 하나로 해석하며 probing과 fallback은 금지합니다.

모델 연결과 profile 값은 명시적인 typed data로 유지하며, 이 unit은 canonical byte encoding이나 durable profile digest를 부여하지 않습니다. 하나의 Provider·Account 정의는 profile 밖에 normalized endpoint 하나를 정확히 선언하고 model entry는 이를 재정의할 수 없습니다. 정의는 model entry 상위에 base profile 하나를 선언할 수 있습니다. 각 model entry는 상속할 field를 생략하거나 닫힌 field `api_dialect`, `tokenizer_profile`, `input_token_limit`, `max_output_tokens`, `reasoning_parameters`, `optional_request_parameters`, `tool_capability_policy`, `replay_profile`만 교체할 수 있습니다. 해석할 때 base profile을 복사한 뒤 model에 명시된 각 field를 재귀 merge하지 않고 통째로 교체합니다. 알 수 없거나 중복된 field, endpoint 누락, 해석 후 필수 profile field 누락은 실패합니다. 모델 profile field를 생략하면 base 값을 상속하지만, base와 model 모두 `max_output_tokens`를 제공하지 않으면 최종 profile에도 그 필드는 없습니다. 빈 mapping을 명시하면 structured field 전체를 빈 mapping으로 교체합니다. Whole-field YAML null을 명시하면 `--from` import와 durable-state decode 경계에서 모두 실패합니다. Null은 존재하는 structured field 아래에서만 재귀 structured-value algebra의 일부로 유지됩니다. Endpoint나 필수 profile field에 implicit default는 없습니다. 알려진 maximum과 모르는 maximum이 섞인 정의는 base에서 `max_output_tokens`를 생략하고, maximum을 아는 model에만 양수를 기록해야 합니다. 필드 생략으로 상속된 base 값을 지울 수는 없습니다. 아래의 replay-profile omission 규칙만 별도의 의미 default입니다.

해석된 effective profile은 모델의 API dialect, tokenizer profile, input-token capability, 선택적인 known maximum-output capability, reasoning parameter, optional request parameter, tool-capability policy, replay profile을 포함합니다. `max_output_tokens`가 있으면 `input_token_limit`보다 작은 양수여야 하고 Yo가 아는 hard maximum을 뜻합니다. 실제로 더 작은 request별 cap은 request context입니다. 필드가 없으면 Yo가 신뢰할 수 있는 숫자 maximum을 모른다는 뜻일 뿐이며 숫자 추측을 허용하지 않습니다. 이 상태는 대응 output field 생략을 허용하는 Connector로만 route할 수 있습니다. 문자열, 0, 음수, boolean, mapping, sequence, null을 이 필드에 쓰면 실패합니다. 필드의 존재·부재 또는 알려진 숫자의 변화는 complete-binding equality를 바꾸고 새 epoch를 엽니다. 각 profile identifier는 정확한 `yo.versioned-profile-id/v1` 문법을 사용합니다. 전체 길이는 1~128 ASCII octet이고, 비어 있지 않은 name은 `[a-z0-9][a-z0-9._-]*`에 맞아야 하며, 그 뒤에 `/v`와 `[1-9][0-9]*`에 맞는 version이 옵니다. Structured profile field는 null, boolean, string, 음수 `i64`, 음수가 아닌 `u64`, 유한한 `f64`, sequence, 고유한 string key를 가진 mapping으로 구성되는 닫힌 재귀 value algebra를 사용합니다. Plain untagged scalar는 하나의 공통 순서로 추론합니다. 빈 plain scalar, 정확한 `~`, 대소문자를 구분하지 않는 `null`은 null이 됩니다. 대소문자를 구분하지 않는 YAML 1.1 boolean 표기 `y`, `yes`, `true`, `on`은 true가 되고 `n`, `no`, `false`, `off`는 false가 됩니다. `i64`로 표현 가능한 음수 정수는 signed, `u64`로 표현 가능한 음수 아닌 정수는 unsigned가 됩니다. 남은 값 중 공통 YAML float 문법이 받아들이는 유한한 숫자는 `f64`가 되고, 나머지 scalar는 string으로 유지됩니다. 정수 digit separator는 숫자 사이에서만 허용하므로 plain `1_000`은 숫자 `1000`입니다. `config.yaml`은 이 범위에서 일반 Session과 TUI 설정만 소유합니다. 모델 정의, catalog seed, startup target, connection provenance, credential path, model-operation snapshot은 소유하지 않습니다. Top-level `model` field는 unknown이고 connect, disconnect, default, startup, resume, live-switch 경로는 `config.yaml`에서 모델 상태를 읽지 않습니다.

`last_failure`는 `connections.yaml`의 optional per-model observation state이며 complete-binding identity도 routing 금지도 아닙니다. 정확한 shape는 `kind`와 `observed_at`이고, `observed_at`은 request outcome의 canonical UTC RFC 3339 whole-second timestamp입니다. 닫힌 kind는 typed Connector/runtime 경계에서 분류합니다. `authentication`은 credential 거절, `access_denied`는 인증 뒤 권한 거절, `model_unavailable`은 exact model 부재·사용 불가, `rate_limited`는 provider throttling, `request_rejected`는 그 밖의 provider-declared client-request 거절, `provider_unavailable`은 provider-side service failure, `transport`는 connection·TLS·byte transport failure, `timeout`은 request deadline·inactivity expiry, `protocol`은 유효하지 않은 status·header·event·terminal grammar, `response_limit`은 설정한 response byte·event·semantic-output 경계, `local_configuration`은 실제 모델 사용에서 dispatch 전에 만난 missing·stale local credential 또는 binding prerequisite입니다. Connector별 status mapping은 이 의미를 보존하고 신뢰할 수 없는 body text에서 더 구체적인 kind를 추론하지 않습니다. Recovery가 conflict이거나 완료할 수 없으면 observation write를 건너뛰고 별도 persistence failure로 보고하며 journal의 expected/planned state 밖에 세 번째 revision을 만들면 안 됩니다. Recovery가 성공했거나 journal이 없으면 두 repository를 다시 읽고 같은 exact complete binding이 계속 current이며 current private CredentialRevision이 request가 캡처한 revision과 정확히 같을 때만 ConnectionRepository CAS 하나를 적용합니다. 분류된 failure는 `last_failure`를 만들거나 교체하고 success는 값이 있을 때 제거합니다. 제거되거나 교체된 binding 또는 중간에 일어난 credential-repository mutation의 stale outcome은 버리므로 이전 credential로 수행한 request가 rotate된 credential의 observation을 쓰거나 지울 수 없습니다. Concurrent request 중 binding과 credential revision이 admission 시점에도 모두 current인 것들의 observation order는 repository commit 순서입니다. User cancellation, local tool execution failure, cleanup failure는 observation을 만들지 않습니다. 저장 값은 warning-only이므로 status와 selection이 보여줄 수 있지만 binding을 disable하거나 deprioritize하지 않습니다. Persistence failure는 원래 request outcome을 다시 쓰지 않습니다. Private CredentialRevision은 `connections.yaml`, status, diagnostic, model-visible state에 복사하지 않습니다. Secret, request body, response body, raw provider error, retry token은 저장하지 않습니다.

`yo connect --from PATH`는 absolute native filesystem path를 요구하고 최대 1,048,576 byte의 UTF-8 YAML document 하나를 import합니다. Exact `--from -`만 유일한 non-path form이며 같은 shape와 byte bound를 standard input에서 읽고, 그 flag 없이 stdin을 추론하지 않습니다. Document는 author-friendly grouped Provider·Account 정의 하나입니다. Key는 `provider`, optional `provider_display_name`, `account`, optional `account_display_name`이고, explicit `base_url`+`profile` 또는 closed `catalog` 중 정확히 하나를 가집니다. 일반 explicit 정의에는 1~4,096개의 `models`가 있고 각 entry는 `model`, optional `model_display_name`, optional whole-field `profile` replacement를 가집니다. 유일한 zero-model explicit form은 아래의 OpenRouter discovery seed입니다. Exact ProviderId `openrouter`, `base_url`, 완전한 base `profile`을 사용하고 `models`와 `catalog`를 모두 생략하며 discovery가 model 하나를 선택하기 전에는 routable ModelTarget이 아닙니다. Catalog 정의도 closed adapter가 membership 또는 inventory를 소유하므로 `models`를 생략합니다. Document는 secret을 포함하지 않고 credential scope 하나가 모든 imported model 또는 discovery operation에 적용됩니다. Document 안 duplicate coordinate, duplicate·unknown field, exact OpenRouter seed가 아닌 빈 explicit model set, 초과한 model set, invalid member, unresolved profile, unsupported catalog combination, unsafe YAML, relative path, input-bound 초과는 preview, credential capture, journal publication, mutation 전에 document 전체를 거절합니다.

Captured repository에 document의 exact Provider·Account pair가 이미 있으면 import는 그 pair의 provider/account label, catalog 또는 OpenRouter discovery seed, complete model-definition set을 한 group 전체로 교체하며 나열한 model을 merge·upsert하지 않습니다. 다른 모든 pair는 byte 의미상 그대로 유지합니다. 제공한 provider display label이 같은 Provider 아래 남아 있는 account와 충돌하면 그 account를 다시 쓰지 않고 batch를 거절합니다. Replacement에서 빠진 model은 사라집니다. 같은 coordinate와 exact complete-binding equality가 replacement에도 있을 때만 기존 `last_failure`를 유지하며, 제거된 coordinate나 바뀐 binding의 observation은 버립니다. Stored preference가 unset, HostTarget, 또는 replacement 뒤에도 남은 ModelTarget이면 유지하고 replacement가 target을 제거하면 지웁니다. Import가 새 model, catalog seed, OpenRouter discovery seed를 preference로 고르지는 않습니다. Prospective preview는 추가·변경·제거 model, 유지·삭제 observation, exact preference transition, credential replacement, discovery-seed transition, resume risk를 보여줍니다. 따라서 catalog-only 또는 OpenRouter-seed-only replacement가 pair의 이전 explicit model을 모두 제거할 수 있으며 그 결과를 preview해야 합니다.

검증된 import는 byte를 바꾸지 않고 그 prospective ConnectionRepository snapshot과 exact pair credential add-or-replace action을 준비합니다. Batch 전체 preview 하나와 confirmation 하나를 사용합니다. Interactive import는 confirmation 뒤 controlling TTY에서만 secret을 받습니다. Non-interactive import는 exact `--from PATH|-, --credential-file PATH, --yes` 조합을 요구합니다. 이 조합의 모든 file `PATH`는 absolute여야 하고 exact `-`는 `--from`에만 허용합니다. 어떤 option도 captured plan을 넓히지 않고 secret은 YAML, preview, diagnostic, log, public state에 나타나지 않습니다. Operation은 독립 생성한 planned ConnectionRevision을 예약하고 exact expected revision, planned revision, byte, preference transition을 불변 public mutation 하나로 결합합니다. Public CAS는 expected 또는 exact planned revision만 받아들이고, exact intended byte와 planned revision이 이미 보이면 idempotent success이며 다른 winner는 conflict입니다. Complete replacement group과 preference transition은 함께 commit되거나 모두 commit되지 않습니다.

Preference-only mutation은 stored preference가 unset일 때 처음 commit한 Local Codex HostTarget 게시, `yo default TARGET`, `yo default --unset`입니다. Connect와 disconnect와 같은 operation lock 아래에서 command는 복구 가능한 pending operation journal을 먼저 해결한 뒤 exact PolicySnapshot, ConnectionRevision, bounded public byte, selection transition을 캡처합니다. Target-specific structural admission 뒤에 ConnectionRepository CAS 하나를 commit합니다. Credential repository를 바꾸지 않으므로 preference-only mutation은 operation journal을 게시하거나 CredentialRevision 또는 credential action을 명명해서는 안 됩니다. Atomic old-or-new ConnectionRepository CAS가 durable recovery owner입니다.

이 public CAS 전에 중단되면 expected repository state가 남습니다. 이후 invocation은 fresh repository·policy snapshot을 캡처하고 structural admission을 반복합니다. CAS 뒤에 중단되면 caller가 성공을 보지 못했더라도 정확한 planned public state는 완전히 commit되므로 caller는 current preference를 확인해야 합니다. 이후 invocation은 새로운 authorization입니다. 요청한 explicit-default outcome이 이미 일치하면 mutation 없이 성공하고, 그렇지 않으면 `yo default TARGET` 또는 `yo default --unset`이 fresh하게 캡처한 revision에서 새 CAS를 수행하여 current preference를 바꿀 수 있습니다. 이후 Local Codex connect는 fresh capture가 계속 unset일 때만 게시할 수 있으므로 current winner를 보존합니다. Public CAS는 한 invocation의 capture와 commit 사이의 concurrent change를 막지만, 별도 invocation 사이에서 winner를 식별하거나 보존하지는 않습니다.

자격증명을 추가하거나 교체하는 외부 `yo connect`는 복구 가능한 serialized operation 하나입니다. Operation lock 아래에서 정확한 CredentialRevision, ConnectionRevision, prospective complete binding set, credential action, preference transition을 캡처합니다. Structural admission, preview, confirmation, secret capture를 수행하지만 model request는 보내지 않고 authentication, entitlement, endpoint acceptance, semantic terminal을 증명하지 않습니다. Explicit `--from` 정의는 remote discovery를 하지 않고 first preference를 발명하지 않습니다. Exact ModelTarget 하나를 선택한 외부 flow만 session-selection 계약이 소유하는 first explicit-choice preference를 게시할 수 있습니다. 사용자가 두 부분 authenticated dynamic catalog flow를 명시적으로 선택하면 ModelId를 고르는 데 필요한 그 catalog의 bounded inventory request만 발생할 수 있습니다. Catalog membership은 entitlement evidence가 아니고 선택되거나 유지된 model에 connect-time semantic request를 보내지 않습니다. 새 secret은 journaled credential commit 전까지 opaque in-memory CandidateSecret입니다.

Credential 저장소와 public 저장소를 함께 바꾸는 connect 또는 disconnect operation의 첫 저장소 commit 전에 orchestrator는 bounded하고 현재 사용자 소유이며 mode `0600`, no-follow인 operation journal을 durable하게 게시합니다. Journal에는 닫힌 operation kind `connect_credential_change` 또는 `disconnect`, operation identity, 정확한 expected/planned ConnectionRevision, prospective non-secret public byte 또는 durable content-addressed artifact, phase, 닫힌 credential action 하나를 기록합니다. Pre-version document에는 format-version, config digest, verification evidence, 폐기한 `profile_digests` field를 기록하지 않습니다. `add`, `replace`, `remove`는 정확한 expected/planned CredentialRevision과 exact pair intent를 기록하고, `preserve`는 expected CredentialRevision만 기록합니다. Secret, CandidateSecret identity, request·response payload, model-use observation은 기록하지 않습니다. Journal 교체는 durable하고 atomic하며 phase `intent`가 durable하기 전에는 저장소 commit을 허용하지 않습니다. Preference-only와 `last_failure` observation mutation은 각각 single public CAS이므로 journal에서 제외합니다.

복구는 같은 operation lock 아래에서 journal의 operation kind와 credential action을 사용합니다. `connect_credential_change`는 action이 정확히 `add` 또는 `replace`여야 합니다. Credential CAS로 exact prepared pair intent를 먼저 commit하고 phase `credential_committed`를 durable하게 기록한 뒤 public CAS, durable `public_committed`, `complete` 순으로 진행합니다. Exact state table은 다음과 같습니다. Expected credential과 expected public이면 commit되지 않은 intent를 abandon하고 retry에서 secret을 다시 받습니다. Planned credential과 expected public이면 prepared public mutation을 commit합니다. Planned credential과 planned exact public byte이면 완료합니다. 나머지는 conflict입니다. `disconnect`는 public CAS를 먼저 commit하고 phase `public_committed`를 durable하게 기록합니다. Action이 `remove`이면 expected credential과 planned exact public 상태에서 prepared credential removal을 commit하고 `credential_removed`, `complete`로 진행하며, planned credential과 planned exact public이면 완료합니다. Action이 `preserve`이면 expected credential과 planned exact public에서 credential mutation 없이 완료합니다. Expected credential과 expected public이면 어느 disconnect intent든 abandon하고, planned credential과 expected public 및 나열하지 않은 상태는 conflict입니다. Journal phase는 저장소 상태보다 뒤처질 수 있고 exact table 비교 후에만 전진할 수 있습니다. 저장소에 없는 commit을 phase가 주장하면 abandon이 아니라 conflict입니다. 복구는 임의 revision 변경에서 ownership을 추론하거나 secret을 복원하거나 revision을 발명하거나 관련 없는 상태를 덮어쓰지 않습니다. Exact retry는 idempotent합니다.

ConnectionRepository 경로가 없으면 revision token `absent`와 binding, account, preference, observation이 없는 표준 빈 snapshot입니다. 최초 writer는 같은 directory에 현재 사용자 소유이고 no-follow이며 mode `0600`인 임시 파일을 배타적으로 만들고 prepared snapshot을 durable하게 기록한 뒤 expected repository revision이 계속 absent일 때만 atomically rename합니다. Concurrent winner가 있으면 다시 읽어 exact intent reuse 또는 conflict로 처리합니다. 기존 write는 bounded regular snapshot, prepared opaque revision CAS, durable atomic replace, old-or-new recovery, unrelated preservation을 사용합니다. 주입된 repository도 같은 의미를 제공해야 합니다.

OpenRouter, QwenCloud, Kimi는 configured Provider로 유지합니다. Base profile은 imported model entry의 반복을 줄일 수 있고 model override는 예외적인 값을 해당 model 옆에 둘 수 있습니다. 저장된 snapshot은 complete resolved 값을 명시적이고 읽기 쉽게 유지하며 custom profile은 advanced import path로 둡니다. OpenRouter와 Kimi는 각각 여기에 설명한 서로 다른 인증된 account-model inventory protocol을 소유합니다. 어느 protocol도 일반적인 Model Connector 책임이 되지 않고 다른 Provider의 wire field를 decode하면 안 됩니다.

OpenRouter Provider·Account binding은 위의 exact zero-model `--from` form일 때만 model entry를 생략할 수 있습니다. Exact ProviderId `openrouter`, normalized endpoint 하나, 완전한 base profile을 제공하고 `models`와 `catalog`를 모두 생략합니다. 이 binding은 routable ModelTarget이 아니라 discovery seed입니다. 어떤 command도 이 seed를 추론하거나 합성하지 않으므로 이 닫힌 form을 import하는 것이 빈 repository에 seed를 넣는 유일한 ingress입니다. Interactive 두 부분 target admission은 닫혀 있습니다. `yo connect Provider:Account`는 정확히 설정된 OpenRouter discovery seed, QwenCloud catalog seed, Kimi catalog seed만 허용하고 다른 모든 두 부분 target을 거절합니다. 이 문단의 인증된 remote discovery는 OpenRouter seed만 수행하며 QwenCloud와 Kimi는 아래의 별도 catalog flow를 따릅니다. OpenRouter command는 기존 path prefix를 바꾸지 않고 normalized endpoint에 `models`, `user` path segment를 덧붙여 인증된 same-origin `GET`을 한 번 수행합니다. In-memory CandidateSecret은 Bearer credential로만 보내고 origin이 바뀐 곳에는 전달하지 않습니다. Same-origin redirect는 최대 3회, 연결 timeout은 10초, response-header timeout은 각 dispatch attempt마다 새로 시작하는 30초, response-body inactivity timeout은 비어 있지 않은 chunk마다 reset되는 30초, absolute deadline은 2분입니다. 성공 response는 JSON media type이고 8,388,608 byte 이하여야 합니다. `data` array는 4,096 row 이하여야 하며 4,097개 이상이면 일부를 자르거나 고르지 않고 row admission 전에 response 전체를 거절합니다. Transport, status, media-type, size, decode 진단은 credential과 response-body 내용을 노출하지 않습니다. 이 범위에는 background refresh, disk cache, automatic retry가 없습니다.

Discovery response에는 `data` array가 필요합니다. Inventory membership과 현재 runtime availability는 분리합니다. Object가 아니거나 string `id`가 없는 row는 표현 가능한 identity가 없으므로 생략합니다. `canonical_slug`가 아니라 `id`를 durable ModelId로 사용하며 유효하지 않은 ModelId도 생략합니다. Identity 검증 뒤에는 disabled row이더라도 exact ModelId의 첫 row가 이기고 모든 duplicate를 무시합니다. Capability, limit, profile의 다른 조건은 그 row를 in-memory inventory에서 제거하지 않습니다. `architecture.input_modalities`, `architecture.output_modalities`, `supported_parameters`는 capability evidence입니다. 각 값은 string만 담은 array여야 합니다. 유효한 array는 duplicate가 없고 순서와 무관한 set으로 해석하며, 알 수 없는 string은 bounded untrusted in-memory metadata로 유지합니다. Capability evidence가 없거나 malformed이면 row를 숨기지 않고 `capabilities unavailable`로 disabled 처리합니다.

최초 runtime capability set은 input과 output capability set이 모두 `text`를 포함할 때 request를 허용합니다. Enabled row는 Yo의 text input·text output boundary로만 호출하므로 `text`와 함께 다른 modality를 광고해도 model을 disabled 처리하지 않습니다. 유효한 row에 text input이 없으면 `text input unsupported`, text input은 있지만 text output이 없으면 `text output unsupported`로 disabled 처리합니다. `tools` 또는 `tool_choice`가 없어도 text model을 disabled 처리하지 않습니다. 이 경우 effective tool policy는 위 configured-policy intersection에 따라 `no-tools/v1`이 됩니다. Configured tool policy가 최초에 지원하는 두 값 밖이면 `tool policy unsupported`로 disabled 처리합니다. Optional `reasoning` parameter는 표시 badge에만 영향을 주고 reasoning parameter를 발명하지 않습니다. Availability와 reason은 ModelId나 durable provider identity의 일부가 아닌 파생 runtime fact입니다. 이후 reviewed runtime modality 또는 policy 지원이 확장되면 provider-specific allowlist나 connection migration 없이 같은 exact ModelId를 다시 평가합니다.

Optional remote limit가 없거나 JSON null이면 configured `max_output_tokens`의 존재 또는 부재를 그대로 유지합니다. `context_length` 또는 `top_provider.max_completion_tokens`가 있는데 양의 정수가 아니면 row를 숨기지 않고 disabled 처리하며, null이 아닌 `top_provider`가 object가 아닌 경우도 같습니다. 같은 stored 정의에 이미 선언된 model이면 imported whole-field override가 우선합니다. 그 밖에는 remote `context_length`가 base `input_token_limit`를 교체하고, remote `top_provider.max_completion_tokens`가 있으면 configured 상태를 그 알려진 양수 `max_output_tokens`로 교체합니다. Remote output metadata가 없고 configured field도 없으면 계속 absent 상태입니다. Endpoint, dialect, tokenizer, structured parameter, replay profile, tool policy는 configured base와 위 capability intersection을 따릅니다. 결과 complete profile이 유효하지 않으면 `profile unavailable`로 disabled 처리합니다. 여러 조건이 동시에 실패하면 concise primary reason은 capability evidence unavailable, text input unsupported, text output unsupported, tool policy unsupported, profile unavailable 순서를 사용합니다. 정규화한 in-memory inventory는 case-fold한 display label과 exact ModelId 순으로 정렬하며 enabled selection은 두 번째 fetch나 추정 metadata 없이 그 정확한 normalized row를 보존합니다.

Remote에서 온 모든 string은 신뢰할 수 없는 terminal data입니다. Picker와 이후 preview는 이를 raw로 쓰지 않습니다. ASCII U+0020~U+007E 밖의 byte 및 ASCII quote와 backslash byte를 되돌릴 수 있는 visible escape로 표시하므로 C0/C1 control, ESC/OSC payload, line separator, bidi control, non-ASCII byte가 terminal state에 영향을 줄 수 없습니다. Remote `name`은 trim한 UTF-8 값이 비어 있지 않고 96 byte 이하일 때만 사용하며, 그렇지 않으면 escaped ModelId를 display로 사용합니다. Picker result는 각각 terminal row 하나만 차지하고 측정한 terminal width에 맞춰 visible ellipsis로 줄입니다. Selected detail과 이후 preview는 완전한 escaped ModelId를 빠짐없이 wrap합니다. Search는 원래 ModelId와 허용된 원래 display name을 비교하지만 query 표시는 같은 safe boundary를 사용합니다. 이 규칙은 표시에만 영향을 주며 exact unescaped ModelId가 request와 durable identity로 유지됩니다.

정규화한 inventory에 유효한 ModelId가 하나도 없으면 picker terminal mode에 들어가기 전에 discovery가 실패합니다. 그렇지 않으면 모든 row가 현재 disabled여도 controlling-TTY picker를 열고 Provider와 Account를 한 번만 보여주며 display name과 ModelId에 대한 local case-insensitive substring search를 지원합니다. 모든 matching inventory item은 visible result row가 최대 8개인 viewport를 통해 접근할 수 있습니다. 처음에는 첫 match에 focus를 둡니다. Up·Down은 result 하나씩 focus를 이동하고 처음과 마지막 result에서 wrap하지 않고 멈추며 viewport는 focus item이 보이는 데 필요한 만큼만 scroll합니다. Search query를 수정할 때마다 전체 match set을 다시 계산하고 첫 result에 focus를 둡니다. Query에 맞는 result가 없으면 focus 없이 picker를 계속 열어 두어 query를 수정할 수 있고 이때 Enter는 아무 동작도 하지 않습니다. Enabled row에서 Enter를 누르면 선택합니다. Disabled row에서 Enter를 누르면 picker를 유지하고 concise availability reason을 보여줍니다. Escape 또는 interrupt는 취소합니다. 각 row는 Model과 간결한 context, output, tool, reasoning, availability 정보를 식별하며 Provider, Account, complete profile을 반복하지 않습니다. 최초 terminal-mode mutation부터 scope-owned cleanup boundary 하나가 selection, Escape, interrupt, render·input failure, panic unwind, ordinary error를 포함한 모든 exit에서 이전 terminal mode를 복원하고 dynamic panel을 제거합니다. Cleanup 뒤에만 선택한 exact ModelTarget을 기존의 간결한 connection preview로 넘깁니다. `--verbose`일 때만 이후 preview가 complete resolved profile을 펼칩니다. Confirmation 전 취소하거나 disabled row를 살펴본 경우 CandidateSecret을 버리고 새 journal, credential mutation, public mutation을 만들지 않습니다.

외부 서비스용 interactive `yo connect`는 explicit import batch 하나 또는 선택된 catalog binding 하나를 등록합니다. 이미 저장된 exact ModelTarget은 binding을 다시 정의하지 않고 Provider·Account credential을 rotate할 수 있습니다. OpenRouter 두 부분 discovery target은 operation lock을 얻고 pending recovery를 해결하고 repository state를 캡처하며 exact stored discovery seed를 해석한 뒤 CandidateSecret 하나로 account-scoped inventory 하나를 가져와 operator가 enabled Model 하나를 정확히 고르게 한 다음 connect plan을 준비합니다. Disabled item은 선택할 수 없고 plan, journal, credential mutation, public mutation을 만들 수 없습니다. Discovery는 모든 model이나 profile default를 추론하지 않습니다. 이후 preview는 정확히 영향받는 binding과 사용량을 공개하고 한 번 확인합니다. Discovery에 쓴 같은 CandidateSecret을 model request 없이 그 pair에 commit합니다. Successful connect는 정의와 credential이 durable하게 등록되었다는 뜻이며 inventory request가 확인한 범위를 넘어 authentication을 증명하거나, 선택 model entitlement, request acceptance, semantic terminal을 증명하지 않습니다. Session-selection 계약은 exact ModelTarget 하나를 선택한 flow에만 first-commit preference를 제공합니다. Grouped import는 replacement·preservation 규칙을 따르고 같은 public CAS가 해당 transition을 binding과 함께 게시합니다.

Stored 또는 imported 정의는 endpoint, base profile, model entry를 authoring하는 대신 built-in catalog adapter profile 하나를 선택할 수 있습니다. `catalog`는 정확한 `yo.versioned-profile-id/v1` 문법을 사용하고 닫힌 in-process registry 하나를 통해 해석합니다. 각 adapter는 정확한 ProviderId, provider display fallback, normalized endpoint, inventory mode, admitted row 하나를 complete binding으로 만드는 데 필요한 typed profile data를 atomically 소유합니다. Release-owned static adapter는 bounded model membership과 닫힌 whole-field per-model replacement도 소유합니다. Authenticated dynamic adapter는 정확한 inventory request·decoder와 닫힌 release-owned behavior overlay를 소유하며, remote membership이나 metadata는 decoder에 명시적으로 할당된 field만 채울 수 있고 실행 동작을 발명할 수 없습니다. 정의는 계속 AccountId 하나를 authoring하며 account 또는 provider display label을 authoring할 수 있지만, `catalog`가 있으면 `base_url`, `profile`, `models`는 없어야 합니다. Provider mismatch, 알 수 없는 catalog profile, 유효하지 않은 adapter row·overlay, adapter가 정의한 duplicate rule 뒤의 중복 ModelId, catalog와 explicit connection field의 동시 사용은 mutation 전에 실패합니다.

Static catalog registry는 정확히 `qwencloud-coding-plan-cn/v1`, `qwencloud-coding-plan-intl/v1`, `qwencloud-token-plan-team-intl/v1`만 허용하며 모두 ProviderId `qwencloud`에 결합됩니다. 각각 normalized endpoint `https://coding.dashscope.aliyuncs.com/v1/`, `https://coding-intl.dashscope.aliyuncs.com/v1/`, `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1/`을 소유합니다. 완전한 base profile과 per-model replacement는 해당 공식 plan 문서에서 도출한 repository-owned typed data입니다. General pay-as-you-go, workspace-dedicated 또는 그 밖의 QwenCloud endpoint는 URL에서 catalog를 추론하지 않고 explicit imported 정의로 유지합니다. 이후 static Provider나 plan을 추가하려면 generic discovery라고 주장하지 않고 검토된 closed-registry 확장이 필요합니다.

Catalog profile은 안정적인 adapter 동작과 service 또는 plan family를 명명하며 content-addressed inventory snapshot이나 entitlement set을 나타내지 않습니다. 각 release-owned static catalog는 고유 row가 4,096개 이하인 결정적이고 network-independent인 table 하나를 가집니다. Authenticated dynamic catalog는 bounded invocation-local snapshot 하나만 보유하고 이를 persist, refresh하거나 durable state로 취급하지 않습니다. 같은 catalog profile 아래 static table이나 dynamic behavior overlay를 갱신하려면 공식 provider-source evidence와 일반 review가 필요하지만 설정이나 durable state를 바꾸지는 않습니다. 제거·부재·변경된 candidate는 이미 저장된 complete binding을 삭제하거나 다시 쓰지 않습니다. Startup은 정확한 durable field를 decode하고 이제 지원되지 않는 binding은 routable하지 않은 quarantined 상태로 분류합니다. 이후 table, snapshot, overlay에서 같은 좌표를 선택했을 때 field가 다르면 implicit migration이 아니라 명시적인 replacement epoch가 됩니다. 이 pre-version decoder를 유지하는 catalog update에서는 유효한 current-shape operation journal의 exact planned public byte가 recovery authority로 유지됩니다. Recovery는 현재 catalog가 새 addition으로는 거절하는 plan도 완료한 뒤 recovered binding을 decodable·removable하지만 selectable·routable하지 않은 상태로 격리합니다. 다른 shape의 journal은 재해석하지 않고 invalid입니다.

Catalog membership은 model이 현재 release-owned table 또는 invocation-local authenticated snapshot의 candidate라는 뜻일 뿐입니다. Account 또는 CandidateSecret에 그 model 사용 권한이 있다는 증거로 표시해서는 안 됩니다. Static row, dynamic metadata, release-owned overlay는 routable complete binding을 만들기 전에 explicit typed text modality, tool support, reasoning presentation evidence, limit, dialect, tokenizer, structured parameter, tool policy, replay profile을 함께 제공해야 합니다. Runtime capability를 지원하지 않거나 complete overlay가 없는 row는 concise reason과 함께 보이지만 disabled 상태로 유지하고 provider-specific allowlist로 유효한 dynamic ModelId를 숨기지 않습니다. Catalog string은 같은 terminal-safe presentation boundary를 통과하며 picker는 기존 search, viewport, cancellation, disabled-selection, cleanup 동작을 유지합니다. Reasoning label은 remote metadata와 effective execution mode를 구분합니다. 검토된 release-owned overlay는 optional remote metadata가 빠졌을 때 더 강한 exact-model fact를 제공할 수 있지만 명시적으로 모순되는 remote 값은 row를 `capability conflict`로 disabled 처리합니다. 이런 overlay가 없으면 missing·malformed metadata는 unknown이며 동작을 넓힐 수 없습니다.

Catalog 정의는 onboarding seed이며 bundled row 전체를 startup에서 routable하게 만들지 않습니다. Interactive `yo connect qwencloud:Account`는 exact stored QwenCloud catalog seed 하나에만 허용합니다. Operation lock 아래에서 command는 pending recovery를 해결하고 repository를 캡처한 다음 credential이나 network request 없이 고정된 in-process catalog를 해석하고 operator가 enabled row 하나를 선택하게 합니다. 취소하거나 disabled row를 살펴보는 일은 credential input 전에 일어나며 journal, credential mutation, public mutation을 만들지 않습니다. Stored catalog의 row를 가리키는 exact `qwencloud:Account:Model`은 paired `--credential-file PATH --yes` non-interactive path를 포함하여 picker를 건너뛸 수 있습니다. 해당 catalog에 없는 ModelId는 explicit `--from` 정의가 필요합니다.

Catalog row 하나를 선택한 뒤 command는 일반 one-binding connect plan과 concise preview를 준비하고 interactive일 때 한 번 확인한 뒤 CandidateSecret 하나를 정확히 읽습니다. Model request는 하지 않습니다. Final repository revalidation, secret-free journal publication, credential-first commit, public commit, recovery, explicit-choice first preference, safe diagnostic은 일반 exact-target external connect 경계를 따릅니다. QwenCloud onboarding은 model-list request, 문서 scraping, Alibaba management API call, background refresh, disk catalog cache, probing, fallback, automatic retry를 수행하지 않습니다.

Dynamic catalog registry는 ProviderId `kimi`와 provider display fallback `Kimi`에 결합된 exact `kimi-platform-ai/v1`과 `kimi-code-membership/v1`도 허용합니다. Platform profile은 normalized endpoint `https://api.moonshot.ai/v1/`을 소유하고 Code membership profile은 normalized endpoint `https://api.kimi.com/coding/v1/`을 소유합니다. 두 profile은 credential, ModelId, entitlement, billing authority를 서로 교환할 수 없는 별도 account product입니다. Credential, URL 검사, failed request로 다른 profile을 추론하거나 fallback하면 안 됩니다. Interactive `yo connect kimi:Account`는 operation lane과 pending recovery를 해결하고 exact ConnectionRepository·credential revision을 캡처하고 CandidateSecret 하나를 읽은 뒤 stored catalog endpoint에 단일 path segment `models`를 붙여 Bearer-authenticated same-origin `GET`을 한 번 수행합니다. 두 profile 모두 same-origin redirect를 최대 3회 허용하고 OpenRouter와 같은 10초 connect, attempt별 30초 response-header, non-empty body마다 reset되는 30초 inactivity, 2분 absolute inventory deadline을 사용합니다. JSON media type을 요구하고 body를 8,388,608 byte로 제한합니다. `data` array가 4,097 row 이상이면 row admission 전에 snapshot 전체를 거절하며 자르거나 일부를 선택하거나 picker를 열지 않습니다. Credential과 response body를 diagnostic에 노출하지 않고 retry, background refresh, disk cache, documentation scraping을 하지 않습니다.

Kimi response는 정확한 top-level `object: "list"`와 `data` array를 가져야 합니다. Object가 아닌 row, `object`가 정확한 `"model"`이 아닌 row, string `id`가 없는 row, invalid ModelId는 사용할 model identity가 없으므로 생략합니다. Identity validation 뒤에는 exact ModelId의 첫 row가 이기고, 첫 row가 disabled여도 duplicate는 모두 무시합니다. 그 밖의 valid unique ModelId는 inventory에 모두 남깁니다. 사용할 `context_length`는 양의 integer여야 합니다. `supports_image_in`, `supports_video_in`, `supports_reasoning`은 optional boolean capability evidence입니다. Missing·malformed 값은 unknown으로 표시하고 동작을 넓힐 수 없습니다. `created`, `owned_by`, unknown field는 identity, entitlement, runtime support를 만들지 않습니다. Kimi는 trusted display label을 제공하지 않으므로 exact ModelId를 표시합니다. Row는 normalized ModelId search key와 exact ModelId 순서로 정렬합니다.

Platform behavior overlay는 exact `kimi-k3`를 recommended flagship row로 만들고, exact `kimi-k2.7-code`와 `kimi-k2.7-code-highspeed`를 available forced-thinking coding row로 허용하며, exact `kimi-k2.6`을 available non-thinking fallback으로 유지합니다. Complete profile과 admission range는 그대로입니다. Platform K3는 remote의 positive `context_length`가 131,072보다 크고 1,048,576 이하일 때 release-owned `max_output_tokens` 131,072와 catalog effort `max`를 사용합니다. 두 Platform K2.7 row는 32,768보다 크고 262,144 이하인 positive value와 release-owned output 32,768, thinking enabled 및 `keep: all`을 사용합니다. K2.6은 같은 input range와 output cap, thinking disabled, `semantic-only/v1`을 사용합니다.

Code membership overlay는 exact `k3`, `k3-256k`, `kimi-for-coding`, `kimi-for-coding-highspeed`만 허용합니다. Exact `k3-256k`가 일상적인 coding을 위한 recommended row이고, exact `k3`는 membership에 따라 context ceiling이 달라지는 같은 flagship identity입니다. 두 K3 profile 모두 `utf8-bytes/v1`, `kimi-chat-completions`, release-owned hard `max_output_tokens` capability 131,072, exact `reasoning_parameters` effort 하나, exact `optional_request_parameters` `{ "thinking": { "type": "enabled", "keep": "all" } }`, `local-tools/v1`, `kimi-private-local-plaintext/v1`을 사용합니다. Catalog는 effort `high`를 만들고 explicit import admission은 exact `low`, `high`, `max`를 허용합니다. `k3`는 membership별 256K 또는 extended ceiling을 반영해 remote context 262,144부터 1,048,576까지 포함해 유지하며, `k3-256k`는 exact 262,144를 요구합니다. 두 모델 모두 overlay가 정한 text-in/text-out·reasoning-required입니다. `supports_reasoning` missing은 이 검토된 사실을 약화하지 않지만 explicit false이면 `capability conflict`로 disabled 처리합니다. Exact `kimi-for-coding`과 `kimi-for-coding-highspeed`는 remote context 262,144, release-owned hard `max_output_tokens` capability 32,768, 같은 tokenizer·dialect·tool-policy·private-replay field, 빈 reasoning parameter, exact optional parameter `{ "thinking": { "type": "enabled", "keep": "all" } }`을 요구합니다. 둘은 text-in/text-out forced-thinking coding row이고 explicit false reasoning capability는 conflict이며 high-speed row는 `high-speed` badge를 가집니다. Code `/models` response는 output limit을 authoring하지 않으므로 이 output 값은 membership service maximum 주장이 아니라 보수적인 Yo hard request ceiling입니다. Agent loop가 별도로 계약된 runtime context policy를 사용해 그 ceiling 이하의 실제 양수 request-local cap을 선택합니다. 현재 또는 미래의 다른 Code ModelId는 complete request·replay 동작이 검토될 때까지 보이지만 `profile unavailable`로 disabled 상태입니다.

두 profile 모두 remote context가 exact closed range 밖이면 row는 `profile unavailable`입니다. 검토된 reasoning metadata가 missing이면 exact overlay fact를 유지하고 explicit contradiction은 capability conflict입니다. Prefix, substring, display label, remote capability flag로 다른 ModelId를 enabled binding으로 바꾸지 않습니다.

`kimi-chat-completions`를 명명하는 모든 새 planned complete binding의 admission은 explicit import 또는 reviewed catalog 어느 쪽에서 왔든 닫혀 있습니다. 모든 variant는 exact ProviderId `kimi`, `utf8-bytes/v1`, `local-tools/v1` 또는 안전하게 좁힌 `no-tools/v1`, 아래에 명시한 exact replay profile을 요구합니다. `https://api.moonshot.ai/v1/`에서 Platform K3는 exact `kimi-k3`, `131,072 < input_token_limit <= 1,048,576`, exact hard output capability 131,072, effort `low`·`high`·`max` 중 하나, 빈 optional parameter, private replay를 요구합니다. Platform K2.7은 exact ModelId `kimi-k2.7-code` 또는 `kimi-k2.7-code-highspeed`, `32,768 < input_token_limit <= 262,144`, exact hard output capability 32,768, 빈 reasoning parameter, exact thinking-enabled-and-preserved optional parameter, private replay를 요구합니다. Platform K2.6은 exact `kimi-k2.6`, 같은 K2 input range와 hard output capability, exact thinking-disabled optional parameter, semantic-only replay를 요구합니다. `https://api.kimi.com/coding/v1/`에서 Code K3는 exact `k3`와 `262,144 <= input_token_limit <= 1,048,576` 또는 exact `k3-256k`와 input 262,144, hard output capability 131,072, effort `low`·`high`·`max` 중 하나, exact thinking-enabled-and-preserved optional parameter, private replay를 요구합니다. Code K2.7은 exact `kimi-for-coding` 또는 `kimi-for-coding-highspeed`, input 262,144, hard output capability 32,768, 빈 reasoning parameter, exact thinking-enabled-and-preserved optional parameter, private replay를 요구합니다. Endpoint·ModelId cross-product, 다른 replay profile, 그 밖의 차이는 일반 model transport 또는 add·replacement의 새 intent 게시 전에 typed unsupported-binding 또는 private-replay-consent-required failure가 됩니다. Kimi Connector는 transport 전에 선택된 variant의 complete envelope를 방어적으로 다시 검사하면서, exact hard capability 이하의 양수 request-local output cap만 허용합니다. Mandatory recovery는 new admission이 아닙니다. 유효한 current-shape journal의 exact planned public byte를 완료한 뒤 unsupported recovered binding을 decodable·removable하지만 selectable·routable하지 않게 quarantine합니다.

Enabled Kimi row를 선택하면 두 번째 fetch 없이 그 exact normalized row와 CandidateSecret을 유지합니다. 취소하거나 disabled row를 살펴보면 in-memory secret을 버리고 새 plan, journal, credential mutation, public mutation을 만들지 않습니다. K3 또는 K2.7 Code preview는 일반 Session이 정확한 tool-loop·resume fidelity를 위해 bounded provider-private assistant state를 current-user-only local Session repository에 암호화하지 않고 보존한다는 사실을 알립니다. `--yes` 또는 interactive confirmation은 그 exact storage fact를 승인하고, 그 뒤에만 connection이 `kimi-private-local-plaintext/v1`을 게시할 수 있습니다. Catalog inventory membership은 entitlement evidence가 아닙니다. Command는 connection-verification request를 보내지 않고 verification cache-affinity hint를 만들지 않으며 선택한 model이 일반 request를 받아들인다고 주장하지 않습니다.

Non-interactive external connect는 explicit합니다. Stored exact ModelTarget credential rotation은 그 target과 `--credential-file PATH`, `--yes`를 요구합니다. Grouped definition import는 `--from PATH|-`, `--credential-file PATH`, `--yes`를 요구합니다. 모든 file `PATH`는 absolute여야 하고 exact `-`는 `--from`에만 유효한 유일한 stdin 예외입니다. 이 조합은 Local Codex에서 거절하고 두 부분 interactive discovery target과 섞을 수 없습니다. `--yes`는 이미 캡처한 unambiguous preview와 repository revision만 승인하므로 target을 넓히지 않고 confirmation만 생략합니다. Command는 pending recovery를 해결하고 plan을 준비한 다음 credential-store 계약을 통해 credential file을 열고 model request 없이 interactive connect와 같은 journal publication·commit을 수행합니다. Credential-file capture failure는 새 operation의 intent나 repository mutation을 만들지 않고 TTY나 다른 secret source로 fallback하지 않으며 source file을 그대로 둡니다. Plan 이전의 mandatory recovery는 기존 journaled operation을 이미 완료했을 수 있습니다. `--verbose`는 interactive confirmation 전용이므로 non-interactive `--yes`와 함께 사용할 수 없습니다.

Interactive disconnect는 stored target 하나를 묻거나 추론합니다. Non-interactive disconnect는 정확한 Provider와 `--account`, `--yes`가 필요하고, `--yes`는 캡처한 plan과 revision만 승인합니다. Prospective ConnectionRepository snapshot에서 target Provider·Account pair의 post-public binding set을 계산합니다. 남는 stored external binding이 그 pair를 계속 요구하면 credential action은 `preserve`이고, post-public dependent가 없을 때만 prepared `remove`를 허용합니다. Preview는 영향받는 binding, preference transition, resume risk, 계산된 credential action을 보여줍니다. Public removal과 preference transition을 credential removal보다 먼저 commit하며 public-first recovery table이 모든 exact crash state를 이어가거나 완료로 인식합니다. Durable history는 유지합니다.

하나의 operation lock이 connect, disconnect, first-commit Local Codex preference 게시, explicit default 설정·해제, 짧은 post-request observation write를 serialize합니다. 모든 command operation은 새 작업을 계획하기 전에 pending operation journal을 해결합니다. CredentialRevision은 credential store와 권한 제한 operation journal 안에서만 private하게 유지합니다. 사용자에게 보이는 typed conflict와 partial outcome은 operation kind, phase, 계산된 preserve/remove action, expected 또는 committed ConnectionRevision과 안전한 retry 안내만 표시하고 CredentialRevision이나 secret은 노출하지 않습니다. Retry는 idempotent하며 관련 없는 data를 복원하거나 삭제하지 않습니다. Tenant 선택과 UI, rotation policy, failover는 미루되, 주입 가능한 경계로 미래 caller-owned tenant scope를 보존하고 지금 TenantId를 추가하지 않습니다.

## 이유

명시적인 resolved field를 사용하면 두 번째 content-addressed identity를 만들지 않고도 durable connection state를 읽기 쉽게 유지하고 equality 진단으로 어느 값이 다른지 설명할 수 있습니다. `connections.yaml` owner 하나는 manual/managed composition과 config race를 없앱니다. Connect-time structural admission과 recoverable credential/public commit은 provider cost와 model-count latency를 피하고, 실제 model use만 authentication, entitlement, request acceptance, semantic success의 authority로 남깁니다. Operation별 recovery는 다른 stored binding이 계속 요구하는 credential을 지우지 않으면서 public-first disconnect를 보존하고, single-store preference 또는 observation mutation에는 cross-repository journal이 필요하지 않습니다.

Inventory와 현재 availability를 분리하면 remote model identity를 안정적으로 유지하면서 Yo runtime 지원을 확장할 수 있습니다. Capability metadata는 유효한 model을 숨기는 대신 effective behavior를 좁힙니다. Tool calling이 없는 text model은 `no-tools/v1`로 계속 사용할 수 있고, Yo가 아직 실행할 수 없는 modality는 정확한 reason과 함께 표시되며 해당 runtime capability를 구현하면 같은 model이 eligible해집니다.
