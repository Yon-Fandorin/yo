# Startup target and Session model selection

## Statement

A startup target is HostTarget or ModelTarget. `host:<HostId>` is the HostTarget namespace. A HostId MUST contain 1 to 64 lowercase ASCII letters, digits, or interior hyphens, and MUST NOT begin or end with a hyphen. The current built-in HostTargets are exact `host:codex` and `host:grok`, displayed as Local Codex and Local Grok. A new stored ProviderId `host` is reserved; a pre-existing durable `host` coordinate remains a qualified ModelTarget with stable credential, attribution, and continuation identity and is never shadowed by the HostTarget. Interactive and non-interactive startup accept one optional `--model TARGET_REFERENCE`.

ModelTarget spellings are `Model`, `Provider::Model`, and `Provider:Account:Model`. Provider and Account canonical percent encoding maps `%` to `%25` and `:` to `%3A`; lowercase, unnecessary, malformed, or non-UTF-8 escapes fail. The Model suffix remains vendor-owned bytes. The resolver compares canonical catalog spellings, deduplicates identical coordinates, and requires exactly one result. A bare canonical `host:<HostId>` is a HostTarget; a ModelId with the same bytes requires qualification. Display names never route.

Bare Model uses the current Provider and Account namespace when one exists, otherwise global exact uniqueness. `Provider::Model` requires exactly one Account. The full spelling decodes its first two segments and addresses the complete coordinate. Zero results are absent and multiple results ambiguous; diagnostics return stable sorted canonical complete coordinates.

Startup captures three selectable sources exactly once: the invocation layer is the optional parsed `--model`; the stored layer is the three-state preference plus complete definitions in the captured ConnectionRepository snapshot; and the injected PolicySnapshot contains admission rules, `allow_user_override`, an optional enforced target, and an optional policy-default target. Absence at each layer is an explicit value, not a parse failure. `config.yaml` supplies no model definition or startup target. PolicySnapshot has exactly two valid forms. The overridable form has `allow_user_override=true`, no enforced target, and an optional policy-default target. The enforced form has `allow_user_override=false`, exactly one enforced target, and no policy-default target. Every other field combination is malformed policy. The initially shipped policy is overridable with no policy-default target and admits Local Codex, Local Grok, and structurally valid stored ModelTargets.

Capturing or structurally decoding any required source is fatal, as are stale repository revisions and malformed policy. These assembly failures are not hidden by a higher target. Enforced form selects its enforced target; a differing invocation target is a fatal policy conflict, while the stored target remains visible only as non-selecting provenance. Overridable form chooses the first present invocation, stored preference, then policy default. There is no implicit target and no built-in HostTarget is ever silently inserted. When all selectable sources are absent, interactive startup enters setup before creating a Yo Session or backend epoch; non-interactive startup fails `StartupTargetRequired` and shows exact `yo connect`, `--model host:codex`, and `--model host:grok` guidance. After a target is selected, missing, stale, unavailable, unsupported, or policy-denied status is fatal with no fallback.

Selection MUST validate the complete binding's replay profile before a Session or backend epoch is created. Every admitted private-replay Kimi binding—Platform exact `kimi-k3`, `kimi-k2.7-code`, and `kimi-k2.7-code-highspeed`, plus Code membership exact `k3`, `k3-256k`, `kimi-for-coding`, and `kimi-for-coding-highspeed`—is routable only with exact `kimi-private-local-plaintext/v1` evidence that came from an explicit import or a Kimi catalog connect whose unencrypted current-user-only storage disclosure was confirmed. A release overlay, catalog profile, ModelId, credential, stored preference, policy target, or absent field is not acknowledgment. Replay-profile omission means only `semantic-only/v1`; every incompatible invocation, default, policy, picker, startup, resume, and live-switch path fails `PrivateReplayConsentRequired` with guidance to reconnect through the disclosed Kimi flow or replace the definition through `yo connect --from`. It MUST NOT silently upgrade, select, or persist private state. K2.6 and every semantic-only binding require exact `semantic-only/v1` and never show the private-retention disclosure.

This unit alone owns the stored user preference: unset, HostTarget, or ModelTarget. `yo default TARGET` persists one admitted choice and `yo default --unset` clears it. The service-binding contract owns their preference-only publication boundary: the shared operation lock and pending-journal recovery precede fresh structural admission and exactly one ConnectionRepository CAS. They publish no operation journal and name no credential revision or action. After a caller-unknown outcome, the current preference must be inspected. Repeating an explicit default command is new authorization: an already matching outcome is a no-op, while a different current preference may be replaced by a new CAS. Local-host connect instead preserves every non-unset preference observed by its fresh invocation. Clearing may make the next startup enter setup when no policy target exists. The interactive picker offers inherited, Local Codex, Local Grok, and complete stored models; a non-interactive value-less command fails.

`yo connect` without a target opens onboarding before Session creation. It offers Local Codex, Local Grok, stored or reviewed catalog choices, and an explicit `--from` definition path without treating any as an implicit default. Selecting Local Codex verifies only that the local Codex backend and stable host identity are available. Selecting Local Grok verifies the installed Grok backend, ACP initialization, and the advertised `cached_token` method against the operator's existing `grok login`; Yo neither captures nor stores that token. Either selection then prepares the preference-only HostTarget mutation owned by the service-binding contract. Selecting an exact external model or importing a grouped definition performs structural admission, preview, confirmation, credential capture, and recoverable publication but no model request; successful registration is not entitlement evidence. A non-interactive external definition uses the exact absolute-path `--from`, absolute credential-file, and `--yes` combination owned by the service-binding contract, with exact `--from -` as the sole non-path exception.

The first successfully committed `yo connect` that explicitly selects one exact HostTarget or ModelTarget and captures an unset stored preference publishes that target. A grouped `--from` import is definition-only: it never selects one of its 1 to 4,096 models, a catalog seed, or an OpenRouter discovery seed, preserves an unset or surviving preference, and clears only a ModelTarget removed by its whole-pair replacement. For a local host, the successful connection outcome is the single preference-only ConnectionRepository CAS. Failure, cancellation, or interruption before that CAS writes no preference; interruption after it leaves the exact preference fully committed even when the caller did not observe success. A local-host retry captures fresh snapshots and publishes only if the fresh preference remains unset; otherwise it preserves the current preference. For an explicitly selected external model, the same public CAS includes the stored binding and preference transition inside the credential-changing journaled operation. Failure or cancellation before durable intent writes no preference; once intent is durable, retry first follows the service-binding `connect_credential_change` recovery table. Only a newly started operation after exact abandonment obtains the secret again. Later successful exact-target connections preserve an existing preference; changing it requires `yo default` or the explicit default-selection UI. Concurrent explicit first connections race on the same public revision: one exact CAS wins, while a loser re-reads the winner's preference and must not replace it implicitly.

Before disconnect or grouped replacement removes targets, selection derives one prospective transition. If the exact explicit ModelTarget preference is removed, the same public CAS clears it; otherwise it is preserved. Preview shows the old value, transition, and effective lower target or setup-required outcome. HostTarget is never cleared by model removal.

`yo model` and `/model` are ModelTarget-only. Preparation validates policy, credential, tokenizer, protocol, the derived connector, normalized endpoint, every resolved effective-profile field including replay profile and its authorization provenance, complete-binding freshness, and staleness. A live TUI switch prepares while the old binding remains usable, rejects an active Turn, atomically closes the old epoch and opens the new one, and leaves the old binding usable on preparation, replay, or publication failure.

Resume selects the newest durable Continuation Anchor before considering an override and never consults stored preference or policy default. With no explicit override it uses the Anchor binding subject to current policy and exact credential availability. Policy denial or missing credential opens history read-only with denial or reconnect guidance and no fallback, Anchor mutation, or epoch. A HostTarget override that identifies the same host adapter is a same-binding confirmation; an exact override equal to the Anchor binding does not create a replacement epoch.

An explicit override naming a different binding is not a startup substitution. Replacement requires both a target that supports exact semantic replay and source-Anchor evidence for an admissible exact replay chain under the continuation-lineage contract, or a separately reviewed provider export that establishes the same semantic boundary and replay-content and contract digests. When the source Anchor covers provider-private replay, exact replacement additionally requires the same complete binding identity and replay profile or an independently reviewed lossless converter; otherwise only the explicitly approved lossy transition may drop that state. A backend-managed-state locator or target capability alone is never replay evidence, and Transcript or Request Audit data cannot be used to synthesize it. Without admissible source evidence, the saved Session remains read-only and the override fails with exact-replay-unavailable guidance; it may offer only the separately approved lossy transition. This rule applies to every backend-managed or local source, not only Codex.

When eligible, the replacement-binding transition owned by the Session continuation-lineage contract binds the source epoch and Anchor, fully committed semantic boundary, target complete binding identity, replay executor, replay-content and contract digests, known cache-loss boundary, and new epoch identity. Replay preparation must complete while the old epoch and Anchor remain unchanged. One atomic durable Journal transition then closes the source epoch, opens the replacement epoch, and publishes its Continuation lineage. Failure leaves the original Anchor and epoch executable when its recorded strategy still works, otherwise it opens the saved Session read-only; it never publishes a partial replacement.

A backend-managed-state binding reconnects only through its recorded locator and verified backend identity. A different binding cannot reuse that locator. Cross-backend handoff remains deferred: a delegated-host live Session has no ModelTarget picker, and an incompatible host resume or live host switch fails until a separately reviewed exact-replay export or explicitly lossy transition can replace backend-owned input providers and record the epoch, semantic boundary, and cache or context loss.

## Rationale

No implicit target keeps missing setup visible instead of silently spending work in a local agent host. Persisting only the first explicitly selected committed target gives subsequent startup a predictable default, while a grouped definition import cannot arbitrarily choose one model and later `connect` operations cannot unexpectedly replace an existing preference. Removing `config.yaml` from model ownership leaves one durable definition and preference source. Treating local-host and explicit default changes as preference-only public CAS operations avoids a fictitious credential transition, while shared serialization and fresh retry keep interruption and concurrency outcomes explicit. Requiring replay evidence on both sides prevents target capability from inventing a prefix that a backend-managed source never exported.
