# Kimi Chat Completions model connector

## Statement

The Model Connector for the explicit `kimi-chat-completions` API dialect MUST implement the Kimi Platform Chat Completions wire over HTTPS with SSE streaming. It is Provider-specific because Kimi's request options, strict tool admission, usage placement, and preserved-thinking requirements materially differ from the provider-neutral `openai-chat-completions` grammar. The Yo-managed backend still selects it only through the effective binding's derived Connector identity and MUST NOT branch on Provider. The Connector accepts only exact ProviderId `kimi`, the `kimi-chat-completions` dialect-and-Connector pair, normalized endpoint `https://api.moonshot.ai/v1/`, and one opaque credential resolved for that exact Provider-and-Account pair. It admits two closed model profiles regardless of manual or managed provenance: K3 requires exact `kimi-k3`, `131,072 < input_token_limit <= 1,048,576`, exact `max_output_tokens` 131,072, `utf8-bytes/v1`, exact reasoning effort `low`, `high`, or `max`, empty optional parameters, either `local-tools/v1` or `no-tools/v1`, `semantic-terminal/v1`, and `kimi-private-local-plaintext/v1`; K2.6 requires exact `kimi-k2.6`, `32,768 < input_token_limit <= 262,144`, exact `max_output_tokens` 32,768, the same tokenizer/tool/verification values, empty reasoning parameters, exact optional parameters `{ "thinking": { "type": "disabled" } }`, and `semantic-only/v1`. Every mismatch fails before transport.

The Connector MUST reject URL user information, query, and fragment components, append only `chat` and `completions` to the normalized base path, and never append another `v1`, probe, or fall back. Redirects are bounded to the exact normalized HTTPS origin. A cross-origin redirect fails before forwarding the credential, model-visible context, tool definitions, arguments, or results. The first catalog profile owns `https://api.moonshot.ai/v1/`; the Connector does not infer `.ai`, `.com`, a Model family, or another endpoint from a credential or URL.

Every request MUST send Bearer authorization, the exact wire ModelId, ordered `messages`, `stream: true`, and the admitted output cap as `max_completion_tokens`. A K3 request additionally sends the selected `reasoning_effort` as exact top-level `low`, `high`, or `max`; it omits `thinking`, `stream_options`, deprecated `max_tokens`, temperature, top-p, penalties, partial mode, response format, dynamic tools, provider cache identifiers, and every other undeclared optional field. A K2.6 request sends `stream_options.include_usage: true` and exact `thinking` `{ "type": "disabled" }`, and omits `reasoning_effort` plus the same undeclared fields. The effective profile and wire variant MUST agree exactly, so neither model inherits an implicit default from the other.

Replay MUST encode the exact ordered system, user, visible assistant content, correlated assistant `tool_calls`, and following `tool` result messages consumed by Kimi. Tool call IDs, function names, exact accumulated argument bytes, and exact result bytes remain independent semantic fields. Every completed K3 assistant round additionally produces one bounded provider-private replay item with schema `kimi.assistant-message/v1alpha1`. Its closed `message` object contains required exact `role: "assistant"`, required string `reasoning_content`, required `content` as string or null, and optional `tool_calls`; no other field is admitted. A `stop` round requires string content equal to the exact accumulated visible bytes and forbids `tool_calls`. A `tool_calls` round uses string content equal to the exact accumulated visible bytes when at least one content fragment appeared and null otherwise, and requires a non-empty ordered `tool_calls` array. Each call contains exactly non-empty bounded `id`, exact `type: "function"`, and `function` with exactly the admitted name and exact completed argument string. The private item's typed visible projection MUST equal one immediately preceding generic assistant message plus its contiguous generic function-call items; refusal is absent. The private item follows that group before any tool result or later message. When constructing K3 `messages`, the Connector emits the private `message` as the single assistant wire object and consumes, but does not also emit, its generic visible projection. Thus each admitted field value is returned unchanged without duplicating the assistant round; JSON object member order is not identity. The item is correlated to the accepted request and binding epoch, is never a frontend observation, Transcript value, Request-trace payload, diagnostic, tool input, or cross-binding generic replay item, and is consumed only by the same exact K3 Connector, complete binding identity, and replay profile. K2.6 MUST NOT produce or consume provider-private replay. An absent, duplicate, misplaced, mismatched, malformed, wrong-schema, wrong-epoch, or unbounded K3 private item fails before a later request and prevents a Continuation Anchor rather than reconstructing hidden state.

Each request carries the existing request-local tool exposure. Disabled exposure, required for connection verification and effective `no-tools/v1`, MUST omit `tools` and `tool_choice`. Enabled exposure is valid only under effective `local-tools/v1` and MUST project the frozen registry as Kimi function tools with `strict: true` plus `tool_choice: "auto"`. Before transport every exposed function name MUST contain 3 to 64 ASCII bytes and match `^[a-zA-Z_][a-zA-Z0-9-_]{2,63}$`. Its parameters root MUST be an object and its complete schema MUST be both valid `yo.tool-schema/v1` and the initial closed Kimi MFJS subset: only `type`, non-empty bounded `description`, `properties`, unique `required`, `additionalProperties: false`, `items`, and a non-empty single-variant-type `enum` are admitted; enum values may be only string, integer, or finite number. The existing Yo byte and depth bounds still apply. An incompatible name, keyword, enum, schema, policy, or exposure fails before any request; `strict: false` is not a fallback.

Every choice-bearing SSE data object MUST have exact `object: "chat.completion.chunk"`, exact `model` equal to the requested wire ModelId, exactly one correlated choice with index zero, and one stable non-empty response ID. The first such `delta` MUST contain exact `role: "assistant"`; a missing, different, repeated, or later role fails. It preserves exact `delta.content` and indexed `delta.tool_calls` fragments using the same contiguous-first-index, stable call-ID, stable function-name, and bounded exact-argument rules as the connector-neutral loop. K3 additionally concatenates every exact string `delta.reasoning_content` fragment, using the valid empty string when none appears, and constructs the closed private message above from the role, reasoning, content-presence, calls, and finish evidence without emitting reasoning as an observation. K2.6 rejects any non-null or non-empty `reasoning_content` because its request disables thinking. A non-string K3 reasoning value, an undeclared delta field, an outer object or model mismatch, multiple choices, changed response identity, malformed deltas, missing or duplicate call identity, inconsistent names, a fragment for an unintroduced index, or content or private data after a finished choice fails closed.

Exactly one finish reason MUST close the choice. `stop` completes a final assistant round and is contradictory when tool calls accumulated. `tool_calls` completes one tool-call round and is contradictory without an accumulated call; any visible content remains part of that same round. `length` is a typed incomplete failure and `content_filter` a typed failed response; neither partial round enters replay or a Continuation Anchor. An unknown, repeated, or contradictory finish reason fails.

Kimi's documented final usage has one semantic meaning but multiple closed wire placements. The finishing choice may carry non-null usage at top-level `usage`, at `choices[0].usage`, or at both locations; when both are present their decoded values MUST be exactly equal. A later OpenAI-compatible empty-`choices` top-level usage record MAY follow only when it carries the same exact `object`, requested `model`, and stable response ID as the choice-bearing stream. Across these representations the Connector MUST derive exactly one semantic usage value: every repeated representation must decode to that exact value, while any difference, second distinct usage, usage before finish, usage on a non-finishing choice, or non-empty choice after finish fails. The value requires non-negative `prompt_tokens`, `completion_tokens`, and `total_tokens` with an exact prompt-plus-completion total; Kimi-specific `cached_tokens` or unknown fields are non-authoritative and ignored after the required fields validate. Missing semantic usage is a typed protocol failure.

The exact un-named `data: [DONE]` sentinel MUST be the final data payload after finish and semantic usage. It MUST NOT be missing, repeated, or carry an SSE event name. Comments and no-data framing may be ignored before `[DONE]`; after it only no-data framing and stream end are valid. Other data after `[DONE]`, invalid UTF-8, or stream end without finish, usage, and sentinel fails instead of completing the Turn.

The first Kimi phase policy uses 30 seconds for a new connection establishment, 5 minutes for each dispatched attempt's response headers, 5 minutes of successful-stream inactivity, 30 seconds of error-body inactivity, and 5 minutes for delivery of each ready connector-neutral observation. A connection clock starts when a new TCP/TLS establishment begins and ends when that connection becomes usable; a reused connection has no new connection phase. A response-header clock starts when each HTTP attempt is dispatched, includes any connection establishment, ends only when complete response headers are accepted, and never resets. After success headers, stream inactivity starts before the first body chunk and resets only on each non-empty raw HTTP body chunk before retention or decoding. After non-success headers, error-body inactivity follows the same start and non-empty-chunk reset rule before retention. Each observation gets one fresh non-resetting delivery wait when ready and completes it only when the consumer accepts that exact observation; network input and prior deliveries do not reset it. Expiry identifies the exact phase.

An optional agent-owned absolute request deadline defaults absent, begins once for one logical request, never resets, and includes every redirect attempt. A separately admitted later request gets a fresh deadline. Connection verification MUST supply a 10-minute absolute deadline. Before any credential-bearing work, the request registers one cleanup boundary that owns the credential and every request resource. Semantic completion, cancellation, every transport, status, media-type, protocol, deadline, or delivery failure, and panic unwind all enter and await that same cleanup before reporting an outcome. Cancellation interrupts operational waits, prevents any new observation, and initiates cleanup, but the already-fired request cancellation token does not cancel cleanup. Cleanup first revokes producer access and observation publication and zeroizes its owned credential; no success, ordinary failure, or typed `Cleanup` failure may be reported before those two invariants hold. It then closes the response body, delivery channel, and request-owned runtime resources under one independent non-resetting 30-second deadline. Deadline expiry or another close or reap failure is a typed `Cleanup` failure only after revocation and zeroization; any remaining disposal stays quarantined without credential access or observation publication. Repeated cleanup is idempotent and does not extend the deadline. Successful headers require media type `text/event-stream`; every other media type fails before SSE decoding.

The first Kimi resource policy retains at most 65,536 error-body bytes, permits at most 1,048,576 bytes in one SSE event and 100,000 SSE events, accumulates at most 1,024 tool calls, 16,777,216 visible-content bytes, 16,777,216 K3 private-assistant bytes, and 4,194,304 function-argument bytes across all calls, and queues at most 256 ready observations. The complete semantic plus private replay delta still fits the existing 16,777,216-byte delta ceiling and the cumulative replay prefix still fits 67,108,864 bytes; the private allowance is not extra capacity beyond those ceilings. Each bound and checked-add overflow is enforced incrementally before retaining an excess byte, item, event, or observation. K2.6 reasoning and every undeclared refusal field have no retention allowance. No diagnostic exposes the credential, response body, model-visible content, tool schema, argument, result, or provider-private reasoning bytes.

The HTTP client MUST disable automatic redirects and retries. The Connector may follow only status 307 or 308 with a valid location on the exact normalized HTTPS origin, at most three times, yielding at most four dispatched attempts under the same absolute request deadline and new per-attempt response-header clocks. Every other 3xx, every non-success status after bounded error-body consumption, and every transport failure terminates without automatic retry. Request-transmission ambiguity and every failure after admitted output likewise terminate; a later caller invocation is a new logical request and authorization rather than a hidden retry.

## Rationale

A distinct dialect keeps Kimi's model-specific request, terminal, and private-continuation grammar out of the provider-neutral OpenAI connector while preserving one backend loop and connector-neutral visible observations. Explicitly accepting only equivalent documented usage placements handles Kimi compatibility without weakening terminal evidence. A schema-bound, hidden, size-bounded replay item lets K3 remain the primary supported model without exposing its reasoning or pretending that visible text alone is exact continuation. K2.6 retains the simpler non-thinking fallback, while models with different forced-thinking profiles remain visible until their own exact overlay is reviewed.
