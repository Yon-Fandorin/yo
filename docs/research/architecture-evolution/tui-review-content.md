## Omitted elements and cross-view transitions to add to integrated inventory

1. **Tool-source navigation (T22/T23/T28/T32):** Chat focused tool → exact Output item → source/copy/find → originating Chat. Current `/output` always latest and current F1 returns Chat; source-target jump is not symmetric with Changes. Existing Output must be strengthened, not proposed as new.
2. **Provenance while scrolled (T30/T31/T46):** Changes Proposed/Recorded/Reported at top → scroll body → narrow header path-priority fallback loses provenance → F1 context. Separate this from general typography.
3. **Diagnostic naming (T33/T34/T38):** F2/F3 are technical record/correlation surfaces, while main header merely says Transcript/Request. Current approval inbox is Chat overlay. No source-copy or pending-inbox claim should be attached to those diagnostics.
4. **Resume vs lineage vs within-session branch (T36/T37):** Yo tree is stored session lineage, Pi tree is entries/branches; Codex session fork picker is another semantic boundary. Compare the user's remembered-content task while keeping data models distinct.
5. **Read-only tree acceptance (T37/T40):** Tree title says read-only but enabled acceptance resumes. Existing selection hints should explicitly name this effect; same concept matters for any diagnostic-looking picker.
6. **Catalog disclosure chain (T35/T39/T40):** static/offline rows, account section, disabled reason, pending snapshot, displayed receipt, reserved next-turn model and committed model are distinct states; text search/preview cannot bypass freshness/publication.
7. **Successful preview → original (T26–T29):** fallback source is not enough. A successfully rendered code/chart/diagram/image needs a deliberate source/copy/open route with retained source identity. `/copy` latest answer is useful but narrower.
8. **Ancillary activity content:** Plan step status, notices, resource links, embedded resources, batch reads/search matches, execution-detail summaries and help/status documents share typed activity rendering. They should be enumerated beneath T22/T25/T59 or as added IDs rather than silently treated as plain tool text. Owners `transcript/layout/activity.rs`, `activity/tool_resources.rs`, `activity/tool_files.rs`; the cross-audit now supplies explicit subitems and representative assertion review in [T22.a–h/T25.a/T29.a](./tui-review-gap.md). Full payload/permutation and real-terminal verification remain unperformed.
9. **Global view switch during overlay (T20/T39/T45):** existing test closes overlay without resurrection; user must know whether returning restores draft only or also picker. Include session/model/request overlay routes separately.
10. **Export meaning:** visual plain-text source generation, external HTML/JSONL export, selected Markdown copy and terminal clipboard transport are different capabilities; neither source retention tests nor CLI help establishes an equally discoverable TUI action.

## Strongest actionable set

P1 candidates grounded in actual paths: human-recognizable resume/tree labels plus content search/preview; focused Output entry route and visible outcome; keep Changes provenance on narrow scrolled header; selected source/element copy; explicit diagnostic-purpose labels; local-vs-global fold hint. Most other findings are preserve/verify/P2 rather than evidence of missing foundations.

No implementation recommendation here requires changing replay/continuation semantics, fetching remote assets from rendering, treating reported filesystem paths as locally readable, or creating a second general panel/query owner. Static tests are substantial but cannot substitute for keyboard-only task runs at 80/40/24 columns, reduced color/motion, ordinary terminal and SSH/tmux.
